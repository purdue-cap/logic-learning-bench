Translated from Microsoft PROSE FlashFill SyGuS SLIA benchmarks (354 files in `sygus/`)
into Delis string-transformation benchmarks.

Generated by `scripts/gen_eqstyle.py` (batch via `scripts/gen_all.sh`).

Encoding (eq-style v2): per-example models observe candidate programs through
demand relations against the expected output rather than forward value
semantics —

- `Str.Eq(e, i, j)` — value(e) equals the expected-output segment [i, j).
  Aspect fields `i`/`j` are Ints trimmed by
  `:where (and (<= i j) (<= j (size (PosOut model))))`.
- `Str.CharEq(e, k, o)` — char k of value(e) equals output char o
  (`:where (< o (size (PosOut model)))`).
- `Str.Len`, `SInt.Sem`, `Str.Val` are functional (`:returns`) over a finite
  `Pos` universe `$0..$B` (B = 2·L, L = longest example string) with an
  `$inv` saturating sentinel, so intermediate strings longer than L keep
  exact lengths.
- `bool.prefixof/suffixof/contains` observe whole values via a `Val`
  universe of `{"", inputs, constants, output}` with exact
  concat/prefix/suffix/contains tables.

`char_ops` (at/substr/int2str with exact per-char demands) is enabled
automatically for single-argument, constant-free cases with L <= 5; other
cases encode those operators conservatively (`false` / `pos.inv`), as do
`str.replace`, `int.to_int`, and `int.indexof` everywhere.

The previous forward (Len, Char) encoding is kept as `scripts/gen_lenchar.py`;
`scripts/compare_eqstyle.py` regenerates it on demand (into
`scripts/.lenchar-cache/`) to compare both encodings. Comparison results live
in `results/`.

Original SyGuS source for each `NNNN.sl` is recorded in its
`(set-info :source ...)` line (mapping in `sygus/MANIFEST.txt`).
